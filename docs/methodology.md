# Методология исследования

## 1. Цель исследования

Цель работы — сравнить влияние ручного, искусственного и совместного обогащения на качество и устойчивость моделей при неизменных исходных данных, разбиениях и правилах оценки. Исследование проводится для текстов Geo Reviews и изображений HaGRIDv2.

## 2. Исходные выборки

Текстовая задача использует 1 000 отзывов Geo Reviews о четырёх сетях быстрого питания. Слабая бинарная метка строится по рейтингу: `0` для оценок 1–2 и `1` для оценок 4–5. Рейтинг, название и адрес организации не должны использоваться как признаки модели.

Задача компьютерного зрения использует подмножество HaGRIDv2 из 34 000 изображений с метками жестов и bounding boxes. Конкретная постановка — классификация или детекция — фиксируется до обучения и остаётся общей для всех экспериментальных режимов.

## 3. Ручное обогащение

К текстовой выборке добавляются 200 отзывов Otzyvru, независимо размеченных двумя участниками по [codebook](fastfood_codebook.md). Расхождения обсуждаются только после завершения независимой разметки.

Для ручного обогащения HaGRID отобраны 200 дополнительных изображений четырёх классов: `like`, `dislike`, `palm`, `fist` — по 50 изображений каждого класса. Два участника работали с изображениями отдельно в Label Studio, проверяя и при необходимости корректируя разметку. Результаты экспортированы и сопоставлены по правилам [codebook](hagrid_codebook.md).

## 4. Искусственное обогащение

Искусственные примеры создаются только на основе train. Для текстов необходимо сохранять смысл и целевую тональность. Для изображений геометрические преобразования применяются одновременно к изображению и bbox. Параметры генерации, фильтрации и случайные seed фиксируются до сравнения режимов.

Искусственное обогащение и обучение моделей на текущем этапе ещё не выполнялись.

## 5. Train, validation и test

Geo Reviews разделён на train/validation/test в размерах 700/150/150 с балансом классов и квотами по брендам. Нормализованные тексты не пересекаются между частями. В режиме `Manual` все 200 отзывов Otzyvru добавляются только в train, поэтому размеры становятся 900/150/150; validation и test не меняются.

Для HaGRID разбиение должно учитывать `user_id`, чтобы изображения одного человека не попадали в разные части. Дубликаты и изображения без пригодной аннотации обрабатываются до формирования разбиений.

## 6. Экспериментальные режимы

| Режим | Состав train |
| --- | --- |
| `Original` | Только исходная рабочая выборка |
| `Manual` | Original и вручную размеченные реальные примеры |
| `Synthetic` | Original и искусственно созданные примеры |
| `Combined` | Original, ручные и искусственные примеры |

Validation и test должны быть одинаковыми во всех режимах одного датасета.

## 7. Метрики

Для классификации сравниваются Accuracy, Precision, Recall и F1; при дисбалансе основным показателем служит macro-F1. Для детекции используются mAP@0.5, mAP@0.5:0.95 и показатели по отдельным классам. Дополнительно фиксируются разброс результатов между seed и ошибки на неизменном test.

## 8. Корректное сравнение

- архитектура, предобработка и гиперпараметры одинаковы для сравниваемых режимов;
- подбор параметров выполняется только по train и validation;
- test используется один раз для итоговой оценки;
- объём добавленных данных и случайные seed документируются;
- результаты нескольких запусков сравниваются по среднему и разбросу;
- ограничения слабой и ручной разметки учитываются при интерпретации метрик.
